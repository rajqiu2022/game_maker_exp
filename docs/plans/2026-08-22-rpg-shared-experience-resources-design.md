# RPG 跨项目经验与资源共享设计

## 背景

`game_maker_exp` 已经沉淀地图场景、建筑遮挡、技能表现、角色与怪物精灵、跨平台 UI、AI 美术与质量门禁，并在远端资源分支中建立了首个水墨武侠图标和 VFX 包。`rpg_map` 项目还积累了多人权威同步、刷怪与动画性能、装备打造路线、跨平台发布、音效反馈，以及一批可复用的幻想 RPG 图标、VFX 和 UI 组件。

本次目标是在不覆盖现有文档、分支或资源的前提下，把这些经验和正式运行时资源整理成可供多个获授权项目采用的公共内容。

## 已批准方案

采用独立资源包与稳定公共文档并行维护的方案：

```text
resource-packs/
├── ink-wuxia-icons-vfx-v1/       # 已有资源包，保持不动
├── fantasy-rpg-icons-vfx-v1/     # 新增技能、物品图标和战斗 VFX
└── rpg-ui-kit-v1/                # 新增 PC、移动端和 HUD UI 组件
```

实现分支从 `origin/codex/shared-art-resource-catalog` 创建。该远端分支是现有经验手册提交的后代，因此新分支天然包含两边内容，不需要覆盖旧分支或强制改写历史。

## 资源准入边界

第一批只收录由项目自制或 AI 生成、已经进入游戏运行目录、来源范围可确认的发布版 PNG。资源必须无角色身份、无剧情文字、无水印，且能够以跨项目语义命名。

明确排除：

- 角色、怪物、地图大图、建筑和地形资源；
- 音频、字体、用户参考图、AI 原始源图、候选和失败资源；
- Godot `.import`、构建缓存、本机路径和项目业务配置；
- 96x96 旧刺客图标、缺少统一 alpha 的超大 RGB 图标；
- 刺客 V2 旧特效、重复阶段主图、`unknown` 和项目专属道具。

每次复制都执行 no-clobber 检查：目标不存在才允许写入；目标存在且哈希相同视为幂等；目标存在但哈希不同则失败并停止。

## 幻想 RPG 图标与 VFX 包

第一版预计包括：

- 23 个标准 256x256 RGBA 技能图标；
- 约 30 个通用装备、药水和材料图标；
- 24 个单阶段战斗 VFX；
- 5 组四阶段 VFX，共 20 张阶段图；
- 7 个正式刺客 VFX。

图标与特效使用跨项目语义 ID，不保留地图名、职业路线、具体等级或内部业务 ID。单阶段和多阶段表现分别在 manifest 中声明 `layout`、帧序、锚点、混合方式、推荐时长和显示范围。

## RPG UI Kit 包

第一版预计包括：

- 42 个按钮、面板、槽位、复选框、进度条和列表组件；
- 12 个移动端摇杆、攻击、交互、药水和功能按钮；
- 8 个角色、队友、目标、资源和基地状态 HUD 组件。

UI 资源保持无文字和语义中立。manifest 记录原始尺寸、拉伸方式、安全区、推荐命中区域和适用平台，避免其他项目只按图片尺寸直接缩放。

## 已有武侠包的采用建议

现有武侠包不在本次修改范围内，只增加采用映射：

- 刺客可采用暗影短刃、暗影处决、迷雾连击、风刃和影步；
- 战士可采用剑气、重劈、裂地、破门和基础命中；
- 通用辅助可采用护盾、治疗、内功光环和反弹水涡；
- 打造材料可采用铁矿石、灵石、玉石和药草；
- 后续武侠职业可以采用掌法、棍法、飞针和太极表现。

本任务只生成适配报告，不直接替换 `rpg_map` 的运行时资源。

## 公共经验扩展

新增六个跨项目专题：

1. 多人权威同步：输入请求、玩家/世界 DTO、定向结果、本地 UI、断线和重连边界。
2. 运行时性能：分批刷怪、兴趣激活、寻路预算、动画与纹理缓存、性能采样。
3. 装备成长：职业过滤、前期过渡装备、推荐打造路线、掉落与背包一致性。
4. 跨平台发布：Windows、Android、Web/微信的地图清单、资源裁剪、版本校验和发布审计。
5. 音效反馈：拾取、攻击、溅射、技能、大招和交互事件的分层、去重和限流。
6. 资源包治理：语义 ID、来源、授权、版本、哈希、冲突处理和跨项目采用。

同步提供必要模板、检查表和 RPG 案例补充。公共文档只描述可迁移规则；具体游戏 ID、路径和数值留在案例中。

## 清单、授权与生成物

每个资源包独立包含：

```text
README.md
LICENSE-ASSETS.md
manifest.json
CATALOG.md
SHA256SUMS
icons/ 或 ui/
vfx/（如适用）
previews/（如适用）
```

仓库根 MIT 继续只覆盖代码、模板与文档。PNG/WebP 采用与现有资源包一致的“仓库所有者项目复用，第三方另行授权”边界。manifest 记录来源类型、处理状态、文件与像素哈希、尺寸、颜色模式和许可状态。

`CATALOG.md`、`SHA256SUMS` 和预览属于生成物，只能由构建工具更新，不能手工维护。

## 验证与错误处理

自动验证覆盖：

- 文件存在、孤儿文件、命名和目录结构；
- 尺寸、RGBA、透明角、主体占用和重复哈希；
- VFX 帧序、非空阶段、锚点和预览；
- UI 安全区、拉伸元数据和目标平台；
- manifest、目录、SHA256 与二进制文件一致；
- 敏感路径、账号、密钥、`.import`、source 和 build 文件禁入；
- Markdown 链接、JSON 解析和仓库全量验证。

若远端分支在实施期间推进，先 fetch，再以非强制方式 rebase 或合并；出现内容冲突时停止并报告，不自动选择任何一方。推送只创建或更新当前新分支，禁止 force push。

## 提交与交付

按以下逻辑分批提交：

1. 设计与实施计划；
2. 公共经验文档、模板和检查表；
3. 幻想 RPG 图标与 VFX 包；
4. RPG UI Kit 包；
5. 校验工具、采用报告和最终链接。

交付报告包括分支、提交记录、资源数量、验证结果、可直接复用映射和未纳入原因。
