# 角色与怪物精灵管线

本章针对 2D 俯视角和 3/4 俯视角角色。目标是建立一套可验证的动画资源契约，避免黑底、方向错误、脚底跳动、动作缺帧和 Boss 只靠放大区分等问题。

## 一、正式动画契约

地面角色和怪物的推荐最低集合：

| 动作 | 用途 | 是否循环 |
|---|---|---|
| `idle` | 站立呼吸、警戒 | 是 |
| `walk` | 移动 | 是 |
| `attack` | 普攻或通用施法 | 否 |
| `hit` | 受击反馈 | 否 |
| `death` | 死亡 | 否，停在末帧或淡出 |

方向为 `down`、`left`、`right`、`up`。右向可以镜像为左向，但必须检查武器手、盾牌、文字和不对称服装。

清单见[动画清单模板](../templates/sprite-animation-manifest.template.json)。

## 二、资产目录与命名

```text
characters/<art_id>/
├── source/
│   ├── identity.png
│   └── attack_right_strip.png
├── frames/
│   ├── idle_down_01.png
│   ├── walk_right_01.png
│   ├── attack_up_01.png
│   └── death_left_04.png
├── qa/report.json
└── manifest.json
```

运行时对象引用稳定 `art_id`，不要直接由敌人业务 ID 拼接文件路径。多个敌人可以共享动画资产，再通过颜色、装备附件或比例配置形成变体。

## 三、为什么不推荐一张超大总表

AI 同时生成多个动作和方向时，常见漂移包括：

- 每行角色脸型、武器和服装不同。
- 方向看似改变，身体仍面向镜头。
- 各动作主体比例不同。
- 网格线和文字被烘焙进画面。
- 脚底位置随帧跳动。

大表格可以做探索性参考，但正式生产推荐“单动作 + 单方向 + 小条带”，逐条验收后再接入。

## 四、生成顺序

1. **身份图**：确定轮廓、配色、武器、材质和战力等级。
2. **右向 walk**：最容易检查身体是否真的侧转和步态是否自然。
3. **下/上方向**：锁定俯视透视和装备一致性。
4. **idle/attack/hit/death**：按已通过方向逐步扩展。
5. **左向**：满足镜像条件时由右向生成，否则单独制作。
6. **处理与 QA**：去底、切帧、归一化、报告和预览。

每通过一组再进入下一组，避免一次生成几十张后才发现身份已经漂移。

## 五、动作节奏

### Walk

至少能看到重心和脚步交替。四帧可使用：接触 → 下沉/经过 → 对侧接触 → 上升/经过。四个方向的移动速度应由代码控制，动画只表达节奏。

### Attack

需要起手、命中和收招。伤害事件绑定命中帧，不要默认第一帧造成伤害。远程单位还要明确弹道生成点。

### Hit

时间短、位移小，不应改变碰撞位置。连续受击需要重启或合并反馈，不能永久卡在 hit 动画。

### Death

死亡后停止寻路和攻击，播放一次，随后保留末帧、淡出或切换尸体资源。不能循环站起来。

## 六、方向选择

根据速度或朝向向量选择主方向：

```text
abs(x) > abs(y) → left/right
否则           → up/down
```

停止移动时保留最后朝向，不要自动回到面朝屏幕。攻击期间使用攻击目标方向，攻击结束再回到移动/待机状态。

## 七、归一化与锚点

- 所有帧使用相同画布尺寸和像素密度。
- 地面单位脚底中点固定到同一基线。
- 可见主体按目标身高缩放，不能每帧拉伸填满画布。
- 攻击刀光等可越出身体边界，但应预留统一安全区。
- 碰撞体不跟随每帧可见边界变化。
- Boss 可以更大，但脚点、碰撞和选择圈要分别配置。

## 八、机器 QA 指标

建议为每个动作/方向生成机器可读报告：

### 结构

- 文件存在且命名匹配清单。
- 帧数、尺寸、颜色模式一致。
- 图片为 RGBA，四角 alpha 低于阈值。

### 主体

- 可见像素覆盖率位于合理区间，防止空帧或主体塞满画布。
- 主体主要连通块只有一个，允许少量武器光点，但拒绝大块背景残留。
- 脚底基线波动在少量像素内。
- 身高和宽度波动不超过项目阈值。

### 动画

- 相邻帧像素差异不能全为零。
- walk 的主体中心不能左右/上下大幅漂移。
- attack 至少有一帧轮廓明显伸展。
- hit 与 idle 有可识别差异。
- death 末帧与首帧有足够变化。

阈值应按资产尺寸校准，不能把示例数字当成所有项目的绝对标准。

## 九、等级与战力可读性

战力层级不应只靠数值和比例：

- 普通怪：轮廓简单、装备少、动作短。
- 精英：增加护甲、角、光效或更强姿态，尺寸小幅提升。
- Boss：独立轮廓、领袖装备、明显前摇和命中动作，画面占比更高。
- 同族高阶：保留家族特征，同时增加材质、武器、颜色层次和动画重量。

过度放大会让碰撞、摄像机和 UI 血条失衡，也容易把普通怪看成几何图形 Boss。

## 十、运行时状态机

```text
death > hit > attack > walk > idle
```

- `death` 一旦进入不可被其他动画覆盖。
- `hit` 有短暂锁定，但可按设计允许死亡打断。
- `attack` 由攻击时间轴控制，不由是否移动直接取消。
- `walk` 只在真实速度超过阈值时播放。
- 资源缺失时退回同方向静态帧，并记录一次警告。

## 十一、常见失败

| 现象 | 根因 | 修复 |
|---|---|---|
| 移动方向正确但脸始终朝屏幕 | 四方向复用了同一源图 | 重新制作方向资源并检查轮廓 |
| 黑色或绿色底图 | 去底失败或导出模式错误 | RGBA/角落 alpha/连通块门禁 |
| 移动没有动作 | 多帧内容重复或运行时没切换状态 | 帧差异 QA + 状态机测试 |
| 角色像在跳 | 脚底基线不稳定 | 归一化画布和脚点 |
| 攻击时伤害时机不对 | 伤害绑定动画开始 | 配置命中帧/归一化时间 |
| Boss 不威猛 | 普通怪放大且动作相同 | 独立 silhouette、装备和节奏 |

## 十二、验收标准

最低可用：方向正确、无背景残留、walk/attack/hit 可播放、脚点稳定。

正式发布：idle/walk/attack/hit/death 和所需方向完整，战力层级可读，在真实地图和目标设备尺寸下通过[精灵发布检查表](../checklists/sprite-release.md)。
