# 跨平台 UI 与触控交互

PC 和手机应共享玩法语义、图标和状态来源，但使用不同布局和输入适配。把 PC 界面整体缩小放到手机上，通常会得到按钮太小、面板遮挡、技能点不到和摇杆方向速度异常。

## 一、三层模型

| 层 | 内容 | 是否跨平台共享 |
|---|---|---|
| Semantic Model | 技能、物品、玩家、商店、任务的状态和操作 | 是 |
| Layout Profile | 锚点、尺寸、安全区、缩放、横竖屏布局 | 否，按平台/分辨率 |
| Input Adapter | 键鼠、手柄、触控、拖拽、长按、取消 | 否，按设备 |

布局模板见[UI 布局模板](../templates/ui-layout-profile.template.json)。

## 二、语义组件

每个可操作组件都应有稳定语义，而不是依赖屏幕坐标：

- `skill_slot.primary_1`
- `consumable.health`
- `interaction.context`
- `panel.shop.buy`
- `inventory.equipment.weapon`

同一语义在 PC 上可以显示快捷键，在手机上显示触控按钮。状态都来自同一个 ViewModel/Presenter，避免一个平台图标更新、另一个平台仍是旧资源。

## 三、触控目标与可见尺寸分离

- 图标可以保持美术设计尺寸，实际触控区域向外扩展。
- 常用操作建议触控边长至少约 `44–48 dp`，战斗主按钮通常更大。
- 相邻高频按钮之间留出间隔，防止误触。
- 购买、关闭、确认等按钮不能只让文字像素可点，整块背景都应响应。
- 用调试开关显示触控矩形，真机检查是否重叠。

具体像素由 DPI、缩放策略和设备决定，不要把某个分辨率的像素值写死为全局标准。

## 四、安全区和布局档

布局需要处理刘海、圆角、系统手势区和不同长宽比：

- 左上：玩家状态、队伍和目标，按安全区内缩。
- 右下：技能和消耗品，避开系统导航区域。
- 左下：移动摇杆，与世界交互按钮保持触点隔离。
- 中央弹窗：最大宽高受安全区限制，内容可滚动。
- 横屏极宽设备：限制面板内容宽度，不让信息分散到两端。

队友头像、血条和复活提示使用统一行高和锚点，不把不同玩家状态动态塞入同一个绝对坐标。

## 五、面板输入隔离

打开背包、商店或打造界面时：

- 暂停或屏蔽战斗触控层，而不是让点击穿透到世界。
- 关闭按钮始终位于内容之上，拥有足够触控区域。
- 一次只允许一个主要面板接收输入。
- 面板关闭后恢复战斗输入。
- 联机中面板是否打开是本地 UI 状态，不进行世界广播。

世界对象变化（买到物品、建筑升级）可以同步，面板本身不能让所有玩家一起打开。

## 六、上下文交互

手机端的手形按钮流程：

1. 世界查询最近合法交互对象。
2. HUD 显示对象名称和可用操作。
3. 玩家点击按钮时立即发出 `interact(target_stable_id)`。
4. 权威端重新验证距离、区域和对象状态。
5. 本地根据结果打开对应面板或显示失败提示。

不要只在触摸移动事件中刷新候选；静止站在宝箱旁点击也必须生效。

## 七、技能按钮状态

主动技能至少区分：

- 未学习：显示但锁定，给出原因。
- 已学习未装备：只在技能/配置界面可选。
- 已装备可用：正常亮起。
- 冷却：保留图标，显示冷却遮罩和数字。
- 资源不足：保留图标，以资源不足样式显示。
- 施法中/瞄准中：显示范围和取消区。

被动技能显示在 buff 或被动区域，标记“被”，不可点击，不应占用主动热键。

## 八、MOBA 式拖拽瞄准

- 按下：捕获该触点，显示技能形状和最大范围。
- 拖动：以起始按钮中心或当前触点计算方向/目标。
- 超出范围：目标夹在合法边界，而不是让技能完全失效。
- 移入取消按钮：高亮取消状态。
- 松开：提交或取消，只处理一次。
- 被系统中断、多指冲突或面板打开：显式取消并清理预览。

范围预览必须与权威端使用同一形状参数，否则玩家看到能命中、服务器却判定失败。

## 九、摇杆速度一致性

左右速度不一致通常来自：

- 摇杆中心/半径使用了错误局部坐标。
- 右向触摸被技能或边缘 UI 截获。
- 输入向量只对一侧完成归一化。
- 屏幕缩放后使用原始像素计算距离。

最终移动向量应先转换到同一坐标空间，再限制长度到 `1.0`。测试上下左右和四个对角的向量长度，不只观察角色位置。

## 十、商店与背包

- 条目固定行高；图标、名称、价格、拥有数量和操作区各有布局列。
- 所有道具槽使用同一外框尺寸，长名称截断或换行，不能撑大格子。
- 拥有数量可以低对比显示，但必须仍可读。
- 小/大生命药、小/大法力药使用不同图标和稳定物品 ID。
- 自动装备快捷消耗品应由购买结果驱动，PC 和手机共用逻辑。
- 装备区域与分类页签不能相互覆盖，窄屏时改用滚动或折叠布局。

## 十一、联机状态

- 玩家等级、生命、法力、装备、技能槽和背包由权威状态同步。
- UI 根据稳定玩家 ID 更新，不根据列表顺序猜测“玩家 1/2”。
- 断线玩家显示明确状态；删除或冻结行由产品规则决定。
- UI 按钮不能直接修改世界对象，只发送命令并处理成功/失败结果。
- 状态重连后完整快照覆盖本地陈旧 ViewModel，再继续接收增量。

## 十二、常见失败

| 现象 | 根因 | 修复 |
|---|---|---|
| 图标可见但点不到 | 触控区域被上层 Control 截获 | 检查 mouse/touch filter 和层级，显示命中区 |
| 建筑交互按钮无反应 | 只刷新目标，没有派发命令 | 点击立即发送稳定目标 ID |
| 技能学习后仍暗 | UI 使用旧槽位快照 | 权威确认后重建语义槽位状态 |
| 装备槽被页签盖住 | 固定坐标叠放 | 使用容器布局和最小宽度 |
| 所有人打开同一面板 | 面板事件被网络广播 | 只同步结果，面板本地控制 |
| 左右移动速度不同 | 坐标空间或归一化错误 | 统一局部坐标并测试向量长度 |

## 十三、验收标准

最低可用：核心按钮在目标手机可点，面板不穿透输入，技能和物品状态与 PC 一致。

正式发布：覆盖主流长宽比和安全区，触控目标可视化测试通过，拖拽施法可取消，联机远程玩家能独立完成技能、宝箱、建筑和商店操作，并通过[手机 UI 检查表](../checklists/ui-mobile-release.md)。
