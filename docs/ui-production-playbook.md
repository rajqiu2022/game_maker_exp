# 数据驱动游戏 UI 生产手册

这份手册解决的是“概念图很好看，接进游戏却难用”的问题。它关注视觉层级、运行资产拆分、状态来源、反馈、Tooltip、头像、品质色和截图验收；平台布局、触控、安全区和联机输入继续参见[跨平台 UI 与触控](ui-cross-platform.md)。

适用范围：2D/2.5D RPG、AVG、回合制或动作游戏中的背包、角色、装备、任务、技能、商店、阅读、战斗 HUD 和系统弹窗。引擎示例以 Godot 术语说明，但原则同样适用于 Unity、Unreal 和自研 UI。

## 一、先写界面契约，不先画整屏

每个界面在出图前至少明确：

- `screen_id` 和用途：玩家来这里完成什么任务。
- 数据来源：名称、属性、数量、状态和权限由谁提供。
- 设计基准与安全内容区：例如 1920×1080 只是示例基准，不是所有平台的固定像素。
- 信息区域：列表、详情、预览、操作、提示和模态框。
- 交互语义：左键/确认、右键/次要操作、Esc/返回、手柄焦点、触控。
- 状态矩阵：空数据、正常、选中、已装备、禁用、加载、失败、长文本和极端数量。
- 资产清单：背景、可伸缩面板、按钮状态、图标、头像、装饰和字体。
- 验收证据：结构测试、固定状态截图、目标设备和已知例外。

可以从[UI 界面契约模板](../templates/ui-screen-contract.template.json)开始，不要把布局、图片路径和业务状态散落在脚本常量里。

## 二、概念图与运行资产必须分层

AI 整屏概念图适合确认构图、材质和视觉气氛，不适合直接承担动态列表、中文正文、数值和交互状态。

推荐流程：

```text
界面任务 → 线框与状态矩阵 → 整屏概念图 → 标注安全区
        → 无字运行资产拆分 → 引擎组装 → 固定状态截图 → 交互回归
```

### 固定展示页与数据界面的边界

| 类型 | 可以整图运行 | 必须拆分 |
|---|---|---|
| 固定主菜单、片头标题页 | 可使用整图状态和透明热区 | 动态账号、版本、活动文案仍由程序绘制 |
| 背包、任务、技能、商店 | 不建议 | 列表、详情、按钮、奖励和滚动内容必须拆分 |
| 战斗 HUD | 只允许静态装饰底框 | 气血、资源、回合、状态、目标和日志动态绘制 |
| 阅读/卷轴 | 可使用无字卷轴底图 | 标题、来源、正文和关闭按钮动态绘制 |

运行资产应尽量无字、无示例数字、无固定条目。重复槽只制作一个母版，运行时按数据数量实例化。背景竹林、人物头发、伪文字和演示图标一旦裁入面板，应视为污染而不是装饰。

## 三、五层模型

| 层 | 职责 | 典型内容 |
|---|---|---|
| Semantic/Data | 唯一真实状态 | 物品、任务、技能、装备、权限、数值 |
| Layout | 区域和响应式规则 | 容器、锚点、最小尺寸、滚动、安全区 |
| Visual Skin | 视觉身份 | 面板、按钮、品质色、图标、字体、装饰 |
| Feedback | 状态变化如何被感知 | Toast、飘字、音效、动画、禁用原因 |
| Input | 如何操作 | 键鼠、右键、手柄焦点、触控、Esc |

数据层决定“能不能做”，UI 层决定“怎样表达”。按钮禁用只是提示，执行命令时仍必须由数据层重新验证；反过来，数据层拒绝也必须返回玩家可读原因。

## 四、设计 Token 和信息层级

不要在每个界面复制颜色、字号和层级常量。至少集中维护：

- 背景、面板、边框、正文、弱化文字、危险、成功、选中和禁用色。
- 标题、分区标题、正文、标签、Tooltip 和操作提示字号。
- 面板间距、列表行高、图标安全边距、按钮最小点击区。
- 世界、HUD、系统面板、对话/模态的层级。
- 品质或稀有度色板。

一套验证过的 RPG 品质色示例：普通 `#c0c8d0`、绿色 `#1eff00`、蓝色 `#4d8fff`、紫色 `#b56cff`、橙色 `#ff9b38`。这是起始样例，不是所有项目必须复用的品牌色。

推荐层级语义示例：世界 `0`、HUD `40`、系统面板 `80`、对话/模态 `120`。具体数值可变，但高层 UI 应进入独立 Canvas/Overlay 层，不能依赖世界角色的 `z_index` 竞争。

## 五、面板、列表和详情区

- 使用容器和最小尺寸表达布局，不用大量绝对坐标堆叠。
- 列表行高稳定；图标、名称、数量、状态和操作各占独立区域。
- 长名称截断或受控换行，不能撑大整个网格。
- 详情区允许滚动；奖励数量、属性行和说明长度都应数据驱动。
- 空列表显示明确空状态和下一步，不留一块看似加载失败的黑区。
- 当前选中、已装备、品质和禁用是四种不同状态，不使用同一个发光边框。

装备界面常用语义：背包中未穿戴的装备显示“装备”；当前角色穿戴的同一实例显示“卸下”；其他角色穿戴的装备不能误报为当前角色已装备。槽位左键可只负责选中和详情，右键执行卸下时必须给出可发现的操作提示。

## 六、按钮和页签状态

按钮的通用基线是 normal、pressed、disabled；指针设备档增加 hover，键盘/手柄档增加 focus，页签等持久选择组件增加 selected。页签的 hover 不能冒充持久 selected。

### 三态资产生产

1. 用一张 normal 母版锁定角饰、边框、画布和 alpha。
2. hover/pressed 从同一母版调色派生，不分别重新生成。
3. 同一输入档所需状态保持同尺寸、同 bbox、同 alpha mask，切换时轮廓不能跳动。
4. 动态文字与底框分层；多语言或数值按钮禁止烤字。
5. disabled 保留正式灰化底框，不能只剩灰色文字。

固定尺寸华丽按钮优先使用纹理按钮；真正需要横向伸缩时才使用九宫格。九宫格 margin 应从不可拉伸角饰实测，不能把暗边或文字纳入拉伸中心。Godot 使用纹理 StyleBox 时需确认按钮没有被 `flat` 配置隐藏底框。

## 七、中文文字可读性

- AI 图片中的中文默认视为不可信；正式文案由引擎字体渲染。
- 用字号、颜色和留白建立层级，不依赖小字号粗体。部分 CJK 字体在小尺寸粗体下会明显发糊。
- 文本区显式配置换行、裁切和滚动，不能只检查字符串存在。
- 正文、标签、禁用文字和品质词条使用不同 Token，但所有层级都必须可读。
- 玩家可见术语统一，不混用开发缩写、内部枚举和多套名称。

验收时必须加入最长中文、空文本、多行说明、极端数值和不同系统缩放。正式发布标准不是“放大截图能看见”，而是目标分辨率和正常观看距离可读。

## 八、图标、头像和品质状态

### 图标

- 图标首先传达类型，再表达个性。剑、刀、棍、掌、暗器、治疗、护体和状态不能都回退到同一个抽象光球。
- 缺图回退按槽位或语义分类，不按文件名猜测。
- 图标在实际显示尺寸检查，不只放大看 256px 原图。
- 品质颜色从数据读取；特殊词条颜色跟随拥有者品质，不在各界面写死。

### 头像

全身身份立绘不能直接缩进小头像框。优先使用独立头像；没有头像时，从同一身份图生成头肩裁切，并让列表与详情共用同一裁切函数。

一个可用起点是：取源图短边约 38% 的正方形区域，水平居中，顶部偏移约源图高度 2%，以 cover 模式显示并裁切溢出。该比例必须可覆写，以适配帽饰、长发和非人角色。

### 品质、选中和装备占用

- 品质：同色名称和持续可见内框。
- 当前选中：独立外框或底色。
- 已装备：角标、文字或槽位标记。
- 禁用：降低整体强调，但仍保留品质身份和原因提示。

## 九、Tooltip、阅读窗和模态框

默认 Tooltip 只适合短句。装备、技能和多属性道具使用结构化自定义面板：名称、普通属性、特殊词条、来源和操作提示分区显示。

- 给 Tooltip 明确最小/最大宽度、内边距和行距。
- 空内容返回 `null`，不弹空框。
- 面板忽略鼠标事件，并钳制在 viewport 内。
- 1、5、10 条属性和屏幕四角分别测试。
- 不要只断言 `visible=true`；错误最常见的表现是 80px 窄框被自动换行撑成整屏高条。

阅读窗应是不可消耗内容的独立展示：长文滚动、重复打开一致、Esc/关闭按钮可退出，阅读行为不应隐式消耗物品或推进任务，除非产品明确这样设计。

模态框必须阻止世界输入穿透，一次只允许一个主面板接收输入；关闭按钮位于内容之上，失败和取消不改变业务状态。不要依赖浏览器/系统原生 alert 作为正式游戏 UI。

## 十、操作反馈和时间轴

业务操作应返回结构化结果，UI 展示实际变化：

- 使用恢复品：显示当前生命/资源实际增加值。
- 永久成长：区分上限增加与当前值增加。
- 解毒/净化：即使数值没有变化，也显示解除的具体状态。
- 装备/卸下：按钮、槽位和角色属性来自同一成功结果刷新。
- 失败：显示原因，不播放成功动画，也不消耗资源。

普通使用和确认使用必须汇入同一业务函数，避免一个界面有反馈、另一个只扣数量。

动画表达状态，不只负责“动起来”。战斗飘字可采用“保持可读 → 上浮淡出”的两段节奏；角色呼吸以脚底为枢轴；技能命中音、受击反应和特效峰值绑定同一事件点。控制器只有在蒙版、特效和淡出全部完成后才能结束行动。

## 十一、截图闭环

结构测试不能发现标题压框、文字太暗、头像太小和按钮跳形。推荐固定截图矩阵：

| 维度 | 最少状态 |
|---|---|
| 分辨率 | 主设计分辨率、窄屏、目标移动设备 |
| 内容 | 空、正常、最长文本、极端数量 |
| 交互 | hover、pressed、selected、disabled、focus |
| 浮层 | Tooltip、确认框、阅读窗、错误提示 |
| 身份 | 五档品质、已装备、其他角色占用、缺图回退 |
| 战斗 | 满血/低血、资源不足、多状态、伤害/治疗反馈 |

截图环境应固定版本、分辨率和播种状态。Autoload/单例可能在首帧恢复默认数据，因此先等待初始化完成，再写入截图状态。调试层默认隐藏，GM/调试面板单独截图。

自动测试负责证明状态、资源和交互正确；人工截图负责判断层级、可读性和视觉语义。两者缺一不可。

## 十二、常见失败

| 用户可见问题 | 根因 | 改进 |
|---|---|---|
| 概念图直接接入后像两层界面叠在一起 | 背景、伪文字和动态区域烤在一张图 | 拆无字底框和动态控件 |
| hover 时按钮轮廓跳动 | 三态分别生成 | 同一母版派生并校验 alpha/bbox |
| 橙装在不同界面颜色不同 | 多份品质常量 | 唯一 QualityPalette，UI 只读取 |
| 全身立绘放进头像框后脸看不清 | 展示语义错误 | 独立头像或共享头肩裁切 |
| Tooltip 变成横贯屏幕的黑条 | 默认短提示承载结构化数据 | 专用详情面板和宽高约束 |
| 已装备物品仍显示“使用” | UI 按类型猜状态 | 按角色+实例查询真实占用 |
| 左键点装备立刻卸下 | 查看与操作混在一个信号 | 左键选中，右键/按钮执行 |
| 物品成功后没有反馈 | 多条业务调用路径 | 汇入统一结果对象并显示差值 |
| 模态框打开后角色仍移动 | 输入层未隔离 | 单一主面板并阻止世界输入 |
| 自动测试全绿但实机字看不清 | 只验证节点存在 | 固定状态截图和人工语义验收 |

## 十三、迁移旧界面

1. 列出现有控件的语义 ID 和真实数据来源。
2. 把烤字、示例数字和重复槽从背景图中剥离。
3. 集中 Token、品质色和层级。
4. 将 selected/equipped/disabled 拆成独立状态。
5. 把默认 Tooltip 升级为结构化面板。
6. 为业务操作建立统一结果对象和反馈入口。
7. 补空、长、错、禁用、边缘位置的测试数据。
8. 先保留旧布局作为回退，再逐屏迁移，避免一次重写所有 UI。

新增可选 Token 或状态通常可保持模板版本；删除字段、重命名语义 ID 或改变交互含义时提升主版本，并提供旧配置映射。

## 十四、完成标准

最低可用：动态数据正确、核心操作可完成、空和错误状态可解释、文字可读、面板不穿透输入。

正式发布：运行资产可追溯；多分辨率和极端内容通过；按钮状态、品质、Tooltip、模态和反馈一致；结构测试、截图矩阵和目标设备人工验收全部有证据，并完成[UI 界面发布检查表](../checklists/ui-screen-release.md)。

真实迁移过程见[武侠 RPG UI 生产经验案例](../case-studies/wuxia-rpg-ui-production-lessons.md)。
