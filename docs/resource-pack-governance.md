# 可复用资源包治理

## 问题

跨项目复制资源最容易出现覆盖同名文件、来源不明、重复占位图、目录混入导入缓存或更新后无法判断影响。资源共享需要像代码依赖一样有身份、版本、授权和可复现目录。

## 适用边界

本文适用于由仓库所有者确认可共享的图标、VFX、UI 与其他运行时资源。未经确认的角色、怪物、地图、第三方参考图、字体和音频不能因“项目里能用”而自动进入公共包。

## 包契约

每个包使用[资源包模板](../templates/resource-pack.template.json)声明：

- 稳定 `pack_id`、语义版本和兼容范围。
- 每个资源的语义 ID、类别、相对路径和技术规格。
- 生成方式、来源说明、权利声明和审核者。
- 预览生成规则、文件摘要和采用报告格式。
- 禁止目录、无覆盖导入与升级策略。

语义 ID 表达用途，不包含机器路径、临时项目名或显示文案。导入工具只复制明确白名单，目标存在时比较摘要：相同则跳过，不同则失败，禁止静默覆盖。

## 目录与生成物

源 PNG 与人工元数据是发布输入；`manifest.json`、`CATALOG.md`、`SHA256SUMS` 和预览由工具确定性生成。CI 重建后要求无差异，并拒绝清单外二进制、导入缓存、构建包和敏感文件。

版本原则：

- 补充元数据或不改变身份的修正使用补丁版本。
- 新增兼容资源使用次版本。
- 删除、改语义 ID、改变锚点或尺寸契约使用主版本。
- 采用项目固定版本，并在升级后生成新增、移除、变更和冲突报告。

## 常见失败

- 直接复制整个美术目录，把源图、缓存和失败候选一起发布。
- 多个文件名指向同一占位图片摘要。
- 仅写“AI 生成”，没有权利范围、审核和来源边界。
- 修改既有包来迁就新项目，破坏旧项目可复现性。
- 把绝对路径写进选择清单或公开目录。
- 只生成预览，不校验运行时原文件。

## 自动检查

- 路径必须相对、规范化并位于包目录内。
- 资源 ID、路径和文件摘要各自唯一。
- PNG 模式、尺寸、alpha、锚点和安全区符合类别契约。
- 清单内文件存在，清单外二进制为零。
- 授权与来源字段非空，禁止目录和敏感模式为零。
- 生成目录重建后工作树无差异；既有包摘要不被新包修改。

## 人工检查

- 所有者逐项确认资源可跨项目共享及允许的使用范围。
- 在实际显示尺寸检查图标辨识度、VFX 阶段和 UI 拉伸效果。
- 用空目标目录执行一次导入，再用已有冲突文件验证拒绝覆盖。
- 在至少一个采用项目中验证路径映射和版本报告。

## 验收标准

### 最低验收

- 包有独立授权、来源、版本、清单和摘要。
- 导入使用白名单且不覆盖冲突文件。
- 公共包不包含缓存、构建产物、机器路径或未授权类别。

### 正式验收

- 构建、预览、目录、摘要和孤儿文件校验均自动化。
- 版本升级提供采用报告和迁移说明。
- 新包加入不会改变已发布包的任何文件摘要。
