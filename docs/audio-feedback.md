# 游戏音效反馈系统

## 问题

拾取无提示、技能只有一个重复音效，或高攻速群伤时音频爆裂，都会削弱操作反馈。把文件路径直接写进玩法代码还会让换音色、平台降级和远程去重难以维护。

## 适用边界

本文覆盖短音效、循环环境音和 UI 提示，不替代配乐编曲、对白本地化或平台音频中间件的专用规范。

## 语义事件

玩法只发语义事件，例如施法开始、武器挥动、命中、暴击、拾取、升级、购买成功和基地摧毁。音频表现通过[音频表现模板](../templates/audio-presentation.template.json)配置候选文件、音量、音高扰动、空间化、优先级、并发组、冷却和回退。

技能音效应至少区分：

- **cast**：动作启动或蓄力，反馈按下成功。
- **release**：弹道或刀光离开角色。
- **hit**：权威命中后播放，可按材质或伤害类型变化。
- **critical/status**：暴击、破甲、吸血等强化反馈，按优先级叠加。

远程客户端依据表现事件播放，不重新推导伤害。事件携带稳定 ID 并去重；本地预测音若已播放，收到确认时不要重复播放同一阶段。

## 限流与优先级

- 同一并发组设置最大声道和最短间隔。
- 高频普攻随机轮换多个轻微变体，避免机械重复。
- Boss 警报、玩家受击和关键 UI 高于普通群怪脚步。
- 超预算时先丢弃远距离、低优先级和重复命中音。
- 文件缺失时使用同类别回退或静默，不阻塞结算。

## 常见失败

- 施法与命中共用一个时间点，远距离技能反馈错位。
- 每个溅射目标播放完整重击音，瞬间占满声道。
- 客户端预测和主机确认各播放一次。
- 不同音源响度差异过大，只在开发耳机上验收。
- 资源路径更名后玩法代码静默找不到文件。

## 自动检查

- 所有语义事件引用存在，候选、回退和总线合法。
- 并发组必须声明上限、冷却和超限策略。
- 音频时长、采样率、声道数和峰值符合平台规则。
- 同一事件 ID 重放只触发一次。
- 压力测试记录峰值声道、被限流数量和音频线程告警。

## 人工检查

- 分别试听施法、释放、命中、暴击、溅射、拾取和 UI 失败反馈。
- 在手机扬声器、耳机和桌面音箱检查清晰度与响度层次。
- 高攻速群怪场景确认关键音仍可辨、没有刺耳叠加。
- 联机观察远程命中音与画面事件同步且不重复。

## 验收标准

### 最低验收

- 核心操作都有语义音效或明确静默设计。
- 高频事件有限流，缺失资源不影响玩法。
- 远程表现按事件 ID 去重。

### 正式验收

- 施法与命中阶段分离，职业与材质有可辨识音色。
- 多设备完成响度、延迟和高并发验收并保存报告。
- 资源、总线、回退和并发规则全部可机器验证。
