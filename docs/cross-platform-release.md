# 跨平台构建与发布闭包

## 问题

编辑器能运行不代表 Windows 与 Android 包含相同内容。地图列表、资源导入缓存、大小写路径、网络协议或导出预设任一不一致，都可能导致房间显示错误地图、版本不一致或运行时缺图。

## 适用边界

本文适用于同一游戏向桌面和移动平台发布。商店签名、主机迁移和在线补丁不在通用模板中强制，但应作为产品级扩展记录。

## 发布闭包

发布闭包是“某个可玩入口实际引用的全部内容”，包括场景、脚本、地图、数据、纹理、音频、着色器和协议版本。联机兼容校验应针对当前房间地图及其闭包，而不是比较双方所有可选地图。

使用[发布配置模板](../templates/release-profile.template.json)声明：

- 产品版本、协议版本和内容版本。
- 各平台导出预设、架构、权限和输入配置。
- 可玩入口及其资源闭包清单。
- 当前地图兼容摘要算法与必需依赖。
- 设备冒烟流程和产物哈希。

构建步骤必须从干净或可复现环境完成资源导入，再导出包；不能依赖开发机残留缓存。包后审计直接读取产物内容，确认闭包中的文件真实存在且路径大小写一致。

## 兼容握手

房间广告公布地图语义 ID、地图闭包摘要、协议版本和玩法规则版本。加入者只比较当前入口需要的字段；失败信息应指出是协议、地图还是依赖摘要不匹配。显示名称不作为兼容身份。

## 常见失败

- Android 导出过滤规则只打包一张旧地图。
- 用地图显示名代替稳定 ID，创建房间后映射到默认地图。
- Windows 文件系统忽略大小写，移动包内路径却找不到。
- 只看项目目录，不审计最终包。
- 修改资源后未重新导入，两个平台使用不同缓存产物。
- 不相关地图缺失导致当前房间被错误拒绝。

## 自动检查

- 从入口递归解析资源引用，生成排序稳定的闭包清单和摘要。
- 两个平台包后审计：关键文件、地图 ID、协议版本和哈希存在。
- 检查大小写冲突、绝对路径、开发文件和未声明二进制。
- 启动包进行短时无界面或自动化冒烟，保存退出码和日志。
- 使用相同地图闭包模拟握手成功，修改一个依赖后模拟失败。

## 人工检查

- 在真实桌面与移动设备分别冷安装、启动和创建房间。
- 双向测试房间发现、加入、当前地图显示和一轮核心玩法。
- 升级安装后检查存档迁移；卸载重装后检查首次资源导入。
- 记录包名、版本、哈希、设备、系统和已知问题。

## 验收标准

### 最低验收

- 两个平台产物由同一提交和内容版本生成。
- 包内包含当前地图闭包，兼容校验只比较当前联机入口。
- 每个平台至少完成一次真实设备冷安装冒烟。

### 正式验收

- 构建、闭包生成、包后审计和握手测试全部自动化。
- 发布证据能追溯提交、配置、产物哈希与设备结果。
- 缺文件、路径大小写和协议差异在进入游戏前给出明确错误。

发布前使用[跨平台发布检查表](../checklists/cross-platform-release.md)。
