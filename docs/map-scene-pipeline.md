# 地图场景生成管线

适用于俯视角 RPG、防守、生存、探索和关卡制游戏。核心目标是让地图可重复生成、可审阅、可验证，而不是依赖编辑器中难以追踪的手工摆放。

## 一、单一规格源

地图应该有一个人和工具都能读懂的作者规格，例如：

```text
maps/<map_id>/authoring_spec.json   可编辑源
maps/<map_id>/runtime/map.json      生成物
maps/<map_id>/runtime/content/*     生成物
build/maps/<map_id>/preview.html    生成物
build/maps/<map_id>/validation.json 生成物
```

只修改 `authoring_spec.json`。如果运行文件不正确，修复规格或编译器，再重新构建。手改生成物会造成预览、测试和实际包内容不一致。

模板见[地图规格模板](../templates/map-authoring-spec.template.json)。

## 二、五段式工作流

```mermaid
flowchart LR
    A[Create 创建规格] --> B[Build 确定性构建]
    B --> C[Validate 结构与连通性]
    C --> D[Preview 可视化审阅]
    D --> E[Test 引擎无界面加载]
    E --> F[目标设备试玩]
```

### Create

从模板建立地图 ID、尺寸、区域、主路线、出生点和基本目标。地图 ID 应小写、稳定、可用于目录和网络协议。

### Build

把网格坐标转换为世界坐标，展开生态簇、生成内容包和运行时对象。构建必须：

- 相同规格和随机种子产生相同结果。
- 默认拒绝覆盖非生成目录。
- 在产物中记录规格版本、编译器版本和内容摘要。
- 不写入机器绝对路径。

### Validate

至少检查：

- ID 唯一且引用存在。
- 出生点、目标点和关键交互点位于地图内。
- 关键路线可达，不穿过阻挡区。
- Boss、掉落、任务和触发器引用有效。
- 碰撞、导航和视觉区域没有明显坐标漂移。

### Preview

预览不需要复刻最终画面，但必须显示区域、路线、阻挡、出生点、NPC、营地、宝箱、Boss、建筑和触发范围。对象应保留稳定 `data-id`，方便工具或审阅者定位规格字段。

### Test

最后由游戏引擎无界面加载实际地图包，捕获解析错误、资源缺失和场景初始化错误。无界面测试通过后仍要在目标设备试玩，因为构图、遮挡、输入和帧率不能只靠结构测试判断。

## 三、地图空间分为四张图

不要用一张背景图同时承担所有职责。

| 空间 | 用途 | 典型数据 |
|---|---|---|
| 视觉空间 | 玩家看到什么 | 地形、贴花、树冠、雾、光效 |
| 碰撞空间 | 角色能否通过 | 墙体、山体、河岸、建筑脚座 |
| 导航空间 | AI 如何移动 | 可行走网格、代价区、动态阻挡 |
| 玩法空间 | 何处触发规则 | 区域、刷怪点、交互圈、任务体积 |

四者共享坐标系和稳定 ID，但可以有不同精度。视觉边缘可以超出碰撞边缘，交互圈也可以大于建筑脚座。

## 四、推荐渲染层级

从后到前：

1. `terrain_background`：烘焙地表或地形块，固定负层级，不参与实体 Y 排序。
2. `terrain_edges`：河岸、悬崖、雪线、道路边缘。
3. `ground_props`：草、碎石、车辙、浅水贴花。
4. `world_entities`：玩家、怪物、掉落和低矮交互物，按脚底 Y 排序。
5. `tall_landmarks`：树木、建筑、塔楼，以脚底锚点排序。
6. `foreground_canopy`：树冠、门楼横梁等可遮挡上半身的前景。
7. `atmosphere`：雾、雪、火光、水汽和区域色调。

### 为什么背景不能参与 Y 排序

大尺寸不透明地形块若按节点原点参与 Y 排序，可能整块盖住角色，表现为角色被水平截断或地图突然变灰。背景层应固定在实体后方；需要前景遮挡的部分拆成透明独立资产。

### 脚底锚点

高物体和角色都以“接触地面的脚点”排序，不以图片中心排序。资产画布可以很高，但运行时原点应落在门槛、树根或角色脚底。

## 五、区域与生态簇

大型地图不要完全随机撒装饰。推荐使用确定性的三层语法：

- **区域轮廓**：雪山、沼泽、竹林、矿岭等大尺度边界。
- **地标**：桥、矿洞、关门、营地和服务建筑。
- **生态簇**：带密度、避让半径、候选资源和稳定随机种子的装饰群。

生态簇必须避让：主路线、出生点、交互圈、战斗场、摄像机关键视野和导航瓶颈。

## 六、建筑和活动子场景

复杂活动区可以在同一世界坐标中使用独立子场景，但必须明确：

- 进入和退出边界。
- 区域内外攻击、寻敌和投射物是否互通。
- 队友是否可以共同进入。
- 摄像机、音景、刷怪和复活规则。
- 小地图如何显示区域和成员。

“视觉上被山脉隔开”不等于玩法上已经隔离。伤害查询、投射物和 AI 目标选择也要使用相同的区域作用域。

## 七、平台画质档

使用一份地图规格生成不同视觉档，不要维护三份地图：

| 档位 | 建议 |
|---|---|
| PC 高画质 | 完整地标、氛围粒子、高分辨率地表、较远装饰距离 |
| 手机 | 降低透明叠层、粒子和同屏装饰，保留路线与地标 |
| 小游戏/低内存 | 地形块流式加载、首包资源清单、远景合批、严格纹理预算 |

玩法对象、碰撞和稳定 ID 必须一致，差异只落在视觉配置和资源包。

## 八、性能经验

- 刷怪按玩家接近范围激活，远处营地不实例化完整 AI。
- 设定单营地存活上限，分小批次、限频补怪。
- 给全局寻路设置每帧预算；预算耗尽时沿缓存路径或短距离直行。
- 大地图按摄像机和预取半径加载地形块。
- 装饰使用稳定随机种子和实例复用，避免每次进图构图变化。
- 透明大图和多层粒子比普通不透明贴图更容易造成移动端过绘。

## 九、常见失败

| 现象 | 常见根因 | 修复方向 |
|---|---|---|
| 角色下半身被切掉 | 地形大块参与 Y 排序 | 背景固定层级，前景拆图 |
| 地图可看但走不通 | 视觉、碰撞、导航不同源 | 构建时共同校验关键路线 |
| 装饰堵住主路 | 随机撒点没有避让 | 使用生态簇避让半径 |
| 一刷怪就卡 | 同时生成过多 AI、全图寻路 | 距离激活、批量预算和缓存 |
| PC 与手机地图不同 | 分别手工维护地图 | 同一规格生成平台视觉档 |
| 联机提示地图不一致 | 校验了客户端全部地图 | 只校验当前联机地图及其依赖 |

## 十、验收标准

最低可用：规格可构建、关键路线可达、引擎可加载、出生点不与建筑重叠。

正式发布还需要：

- 平台档位都使用相同玩法坐标和对象 ID。
- 关键区域有明确视觉语言，路线可读。
- 前景遮挡不覆盖脚底和关键读图。
- 同屏高峰怪物下输入、UI 和移动仍有响应。
- 使用[地图发布检查表](../checklists/map-release.md)完成目标设备验收。
