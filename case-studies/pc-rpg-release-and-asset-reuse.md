# 八章单机 RPG 的发行回归与素材复用

本例取自一个 Godot 4.6.2 单机武侠 RPG 的 Windows x64 制作记录。游戏源码检查点为 `495775629fda`。以下做法分别经过场景或分支验证；数字给出当时的样本范围。

| 遇到的问题 | 采用的办法 | 可复做的检查 |
|---|---|---|
| 章节结算成功，下一座城却无法进入 | 把结算、跳转、城市准入、存档和重启串成一条路线，记录目的地与落脚点 | 同一选择前存档分别走救人、追使，两条线都打完古寺再进入下一章。仅打开场景文件无法覆盖来源门禁 |
| 多方对白、音乐和人物动作结束后要接战，跳过或读档可能重复开战 | 让完整播放和跳过走同一处战斗交接点，保存已胜和已交接状态 | 从演出前、演出中、胜利结算后分别冷读，记录开战次数和战后通行。验证证人选择时同时看站位 |
| 抗性装备和解控队友都能拿到，但很难判断价值 | 留一份正常入口前的存档，固定敌人和队伍基线，每轮只改防护方案；记录实际伤害和耗药量 | 地下档库对照无防护、主角佩戴防毒饰品、携带解毒队友。三组全队毒发掉血为 282、210、196，用药为 23、21、18。数据只代表这次实战 |
| 通用散兵复用后，兵器、方向和落败姿势发生错配 | 分开登记角色身份、武器动作、左右朝向、脚点和可共享特效；按实际招式逐帧选用 | 在剧情入口实打，截待机、命中、受击、倒地和归位。并排看主角与敌人的比例；倒地帧要看脚和武器有没有被切掉 |
| 放大 HUD 后，头像和地图边缘暴露低精度 | 头像从同一立绘裁切，小地图复用场景几何和铺面；分别量屏幕显示、底图和遮罩尺寸 | 同机位拍改前改后。加载旧档核对原已探索区域，走动揭雾、保存、退出再读。该项目逐格核对了 267 个旧探索格 |
| 编辑器里可用的资源在发行包里缺失 | 把运行文件、导入映射和构建依据列入清单；核对带原始字节校验的文件和 Git LFS 实体 | 本轮源码检查点的 30,754 份非缓存运行输入与已验发行包逐份相符。此前的发行测试另在隔离环境用过新档和跨章旧档，这次提交检查没有重新跑完八章 |

新项目可先取一个实际入口、一份可恢复的旧档和一个有两种准备方式的挑战，把人物、任务旗标、奖励和资源读取一起测通，再扩展到后续章节。资源选型和按 ID 导出可沿用[运行素材复用方法](../docs/runtime-art-reuse.md)。
