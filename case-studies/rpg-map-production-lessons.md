# 俯视角 RPG 地图制作经验复盘

## 项目背景

一个受经典自定义 RPG 地图启发的 Godot 4 俯视角项目，需要同时支持地图生成、波次防守、野外练级、服务建筑、技能选择、装备成长、PC 和 Android 局域网联机。随着内容快速扩展，地图视觉、动态资源、触控和远程状态同步暴露出一批重复问题。

本案例只总结可迁移经验，不包含项目美术成品和业务代码。

## 用户可见问题

- 大地图分块参与 Y 排序，角色被水平截断，严重时画面像被灰色块盖住。
- 服务建筑图片重复、比例不统一，角色进入屋顶后完全看不见。
- 怪物有黑底、始终面向屏幕、没有移动/攻击/受击/死亡动作；Boss 只是普通怪放大。
- 刷怪时主线程全图寻路造成卡顿。
- 技能图标、动作、数值、特效和音效散落在多处硬编码，职业表现趋同。
- 手机技能、宝箱、建筑和商店按钮偶尔可见但无法点击。
- 远程玩家的等级、装备、技能槽、建筑交互和基地状态不同步；打开建筑时所有玩家一起弹面板。

## 根因

### 地图既是图片又是逻辑

视觉地表、碰撞、导航和玩法触发没有清晰分工。大图节点默认参与实体排序，装饰随机撒点没有避让关键路线。

### 资产没有正式契约

早期资源只要求“有一张图”，没有动作、方向、alpha、锚点和帧差异门禁。占位图因此长期混入正式目录。

### 表现和结算耦合

角色控制器根据技能 ID 选择特效并结算伤害，新增职业持续增加分支。联机客户端难以判断自己应该请求、结算还是只播放。

### PC 输入被直接映射到手机

按钮视觉尺寸被当成命中区域，面板层级拦截触摸，世界交互只更新候选而未在点击时立即发送请求。

### 网络同步对象边界不清

世界状态、玩家状态和本地面板状态没有分层，导致漏同步或广播过度。

### 成长、性能和发布缺少闭环

前期配方集中依赖挑战材料，玩家很久没有可用提升；集中刷怪把生成、寻路和表现堆到同一帧；桌面与移动包没有按当前地图生成一致的发布闭包。这些问题表面上属于不同模块，实际都缺少从规格到自动检查再到真实设备验收的闭环。

## 采用方案

### 地图规格与五段式工具链

建立唯一作者规格，通过 create、build、validate、preview、test 生成地图包。地表、边缘、地面装饰、实体、高物体、前景和氛围分层，背景固定在负层级，高物体统一脚底锚点。

对应公共指南：[地图场景生成管线](../docs/map-scene-pipeline.md)。

### 确定性生态与性能预算

区域装饰使用稳定随机种子和避让半径；营地只在玩家接近后激活，限制存活数和补怪批次；全局寻路设置每帧预算并复用缓存路径。

### 建筑四边界

建筑视觉、碰撞脚座、交互圈和淡化区独立。玩家进入遮挡区时只 tween 屋顶/视觉 alpha，多人覆盖使用引用计数；面板只在操作玩家本地打开。

对应公共指南：[交互建筑与半透明遮挡](../docs/building-occlusion.md)。

### 动态精灵清单

怪物资产升级为 `idle/walk/attack/hit/death × 四方向` 清单。源图按动作/方向生成，处理脚本完成去底、切帧和脚点归一化，测试检查透明角、连通块、帧差异和目录完整性。精英和 Boss 使用不同轮廓与动作重量，而非只调 scale。

对应公共指南：[角色与怪物精灵管线](../docs/character-monster-sprites.md)。

### 技能定义和表现控制器

技能数值、效果和目标规则留在 gameplay data；图标、角色动作、施法/命中 VFX 与 SFX 进入独立表现配置。主机唯一结算并广播标准化表现事件，远程客户端只重放。

对应公共指南：[可配置技能表现系统](../docs/skill-presentation.md)。

### UI 语义、布局、输入三层

PC 与手机共享技能槽、消耗品、交互和面板操作的语义 ID；布局按设备档配置；输入分别由键鼠和触控适配。手机技能使用按下显示范围、拖动瞄准、取消区松手取消的流程。

对应公共指南：[跨平台 UI 与触控](../docs/ui-cross-platform.md)。

### 权威状态与本地界面分离

远程操作统一为请求，由主机校验技能、装备、拾取、建筑和入口条件，再返回带修订的结果。等级、背包、技能槽和基地生命进入可恢复快照；建筑面板、背包选中项等只留在发起者本地。一次性表现按事件身份去重。

对应公共指南：[多人联机权威状态](../docs/multiplayer-authority.md)。

### 过渡装备与推荐路线

按职业建立起步、过渡、核心和终局节点，前期普通材料即可打造，挑战材料只控制后续跃迁。不匹配职业的掉落保持在地面并显示提示，不能先删对象再拒绝入包。

对应公共指南：[装备成长与推荐路线](../docs/equipment-progression.md)。

### 峰值预算、音效限流与发布闭包

刷怪改为分批创建，远处单位按兴趣激活，寻路按帧排队；高攻速和溅射表现限制粒子、飘字与音效并发。桌面和移动构建从当前可玩地图递归生成资源闭包，联机只比较当前地图、协议和必需依赖。

对应公共指南：[运行时性能预算](../docs/runtime-performance.md)、[游戏音效反馈系统](../docs/audio-feedback.md)和[跨平台构建与发布闭包](../docs/cross-platform-release.md)。

## 被否决方案及原因

- **整张地图烘焙成一张背景图**：构图稳定，但碰撞、动态活动和移动端内存难维护。
- **完全随机生成装饰**：实现简单，但会堵路、遮挡建筑且每次画面不一致。
- **永久降低建筑透明度**：角色可见，但建筑失去质感，且没有解决脚点排序和交互边界。
- **一张大精灵表生成所有动作**：批量快，但身份、方向、比例和锚点漂移难以修复。
- **每个技能写专属代码分支**：短期直接，长期让数值、表现、输入和网络无法独立迭代。
- **广播 UI 打开事件**：能让主机看到结果，却错误地控制了所有玩家本地界面。

## 自动验证

项目逐步加入了：

- 地图规格编译、预览、引用和连通性测试。
- 建筑资源 alpha、主体连通块和层级测试。
- 动画清单、帧目录、透明通道和运行时状态切换测试。
- 技能配置、表现资源、联机事件和回退路径测试。
- 手机 HUD 布局、触控交互、技能拖拽和背包/商店回归测试。
- Godot editor/headless 和短时主场景运行。

扩大回归仍可能存在历史基线失败，因此每批修改都保存修改前失败集合，只接受没有新增失败的结果。

## 人工验收

自动检查之后仍需：

- 在真实地图背景观察角色脚底、建筑遮挡和前景层级。
- 播放全部怪物动作和方向，确认不是重复帧或静态贴图。
- 在 PC 主机和 Android 远程设备完成技能、拾取、建筑、商店、活动入口和基地失败流程。
- 在峰值刷怪和高攻速下观察输入延迟、帧率、音效堆叠和网络状态。

## 结果

最重要的改进不是某一张图，而是生产边界变得清楚：规格可以重建地图，资产有清单和 QA，技能表现不再决定伤害，手机 UI 不再复用 PC 坐标，联机 UI 与世界状态分开。

## 可迁移结论

1. 用户看到的视觉 Bug 往往来自数据边界错误，而不只是图片质量。
2. 美术资源越依赖 AI 批量生成，越需要机器可读契约和拒收门禁。
3. “能加载”与“能游戏”之间必须有引擎测试和目标设备验收。
4. 联机系统中，输入是请求、世界状态由权威端决定、表现是可重放事件、面板是本地状态。
5. 跨平台不等于一套布局缩放，而是共享语义、分离布局和输入。

## 项目参数不是通用规则

本案例中怪物批次、路径预算、装备等级、材料数量、超时秒数和目标设备均是当时项目参数。公共指南只复用权威状态、过渡装备、性能证据、音效限流和发布闭包等方法；采用项目必须通过自己的玩法节奏与设备数据重新定值。

## 不适用范围

- 纯 3D 角色骨骼动画需要补充骨架、蒙皮、动画重定向和 LOD 管线。
- 服务器权威的大型 MMO 还需要兴趣管理、预测、回滚和分区服务。
- 手工像素动画对色板和逐像素修帧要求更高，但动作清单和锚点门禁仍适用。
