# 武侠 RPG 数据界面生产经验

## 项目背景

一个 2.5D 单机武侠 RPG 使用 Godot 4 制作，主要界面包括探索 HUD、角色与队伍、背包装备、任务、武学、商店、可阅读残页、战斗 HUD 和结果页。美术方向先由 AI 整屏概念图建立，再拆成正式运行资产；界面需要同时承载中文长文、动态数值、多品质装备、主动/被动武学、状态图标和键鼠操作。

本案例只保留可迁移的界面经验，不包含游戏业务 ID、原始图片、字体文件或项目路径。

## 用户可见问题

- 整屏概念图直接接入后，外层山景、装饰框、程序文字叠在一起，像两个界面重合。
- 按钮有文字但看不到正式底框；hover/pressed 切换时边角跳动。
- 深色面板上的正文太暗，小字号粗体中文发糊。
- 全身立绘缩入头像框后脸部只有十几像素，队伍列表和角色详情裁切还不一致。
- 同一件高品质装备在背包、角色、Tooltip 和战斗日志显示不同颜色。
- 已装备物品仍显示“使用”，点击右侧装备槽会立刻卸下，玩家无法先查看属性。
- 多属性 Tooltip 被拼成横跨屏幕的黑条，另一版又因宽度过窄变成整屏高条。
- 使用成长道具只减少数量，没有说明生命上限、当前生命和状态到底改变了什么。
- 状态图标存在但不知道含义和剩余回合；确认框打开后，方向键仍可能让世界角色移动。
- 自动测试显示控件存在、资源可加载，实机截图仍暴露压框、遮挡、裁字和对比度问题。

## 根因

### 概念图被误当运行时真值

整屏图同时包含构图、示例内容和装饰。动态列表、文字和按钮再叠上去后，视觉层级和数据边界都失控。

### 状态没有单一来源

界面按物品类型猜“装备/使用”，按本地常量猜品质色，selected/equipped/disabled 又共用同一个高亮，多个界面逐渐漂移。

### 默认组件承担了超出能力的内容

默认 Tooltip 适合短句，却被塞入十条属性；全身立绘被当头像；普通按钮样式被当正式多态纹理；节点可见被误认为布局正确。

### 表现反馈与业务结果分叉

普通使用、珍贵物品确认、战斗内使用和队友使用各自实现，导致只有部分入口显示实际效果。

### 缺少固定状态截图矩阵

测试只覆盖资源和节点，没有把空数据、长文本、边缘 Tooltip、已装备、禁用和模态状态放进同一批实机证据。

## 采用方案

### 概念图只负责方向，运行资产负责组装

整屏图确认颜色、材质和区域比例后，拆为无字背景、可伸缩面板、重复槽、按钮状态和语义图标。标题、列表、正文、奖励和数值全部由引擎生成。

固定主菜单允许使用整图状态和透明点击热区；背包、任务、技能、商店等数据界面禁止整图运行。

### 建立语义、布局、皮肤、反馈、输入五层

物品实例、装备槽、任务状态和武学权限来自唯一数据层；容器负责布局；皮肤读取统一 Token；操作返回结构化结果；键鼠、手柄和触控只做输入适配。

UI 禁用与数据层拒绝保持一致：按钮不可用时显示原因，执行命令时仍重新检查，避免状态更新一帧后绕过限制。

### 分离品质、选中和占用

- 品质使用同色名称和持续可见内框。
- 当前选中使用独立外框。
- 已装备使用角标或槽位状态。
- 禁用降低强调，但保留品质身份和失败原因。

装备操作按“当前角色 + 物品实例”查询真实状态。背包按钮显示“装备/卸下”；右侧槽位左键只选中并显示详情，右键卸下，同时在 Tooltip 中明确操作提示。

### 结构化 Tooltip 和阅读窗

装备 Tooltip 拆分为名称、普通属性、特殊词条、来源和操作提示，并设置明确宽度、内边距、行距与屏幕边缘钳制。空文本不创建面板。

长文残页使用独立阅读窗：标题、来源和正文动态排版，正文可滚动，Esc 和关闭按钮都能退出；阅读不消耗物品，也不隐式改变任务状态。

### 统一头像裁切

优先使用独立头像。没有头像时，从同一全身身份图取短边约 38% 的头肩正方形区域，允许按角色覆写。队伍卡与详情共用同一函数，以 cover 模式显示并裁切溢出。

### 业务结果驱动反馈

普通使用和确认使用汇入同一调用路径。调用前后计算实际差值，Toast 明确显示：

- 当前生命/资源变化；
- 生命/资源上限变化；
- 解除的中毒、虚弱等状态；
- 失败原因和未消耗资源。

战斗状态图标显示剩余回合，悬停立即出现固定尺寸说明；伤害数字先保持可读，再上浮淡出。命中音、特效峰值和受击反应绑定同一表现事件。

### 固定截图闭环

每次界面变更同时跑结构测试和 1920×1080 实机截图。截图在 Autoload 初始化完成后播种状态，默认隐藏调试层，并覆盖：空、正常、长文本、多奖励、Tooltip、模态、禁用、已装备和缺图回退。

采用方法详见[数据驱动游戏 UI 生产手册](../docs/ui-production-playbook.md)。

## 被否决方案及原因

- **整屏概念图直接作为背包/任务背景**：短期接入快，但烤字、示例槽和背景装饰无法适配动态内容。
- **normal/hover/pressed 分别生成**：边角、宝石和透明轮廓不一致，切换时明显跳形。
- **用九宫格拉伸所有按钮**：角饰、暗边和固定文字会变形；固定华丽按钮更适合纹理按钮。
- **所有装备状态只用一圈高亮**：品质、选中和占用无法同时表达。
- **默认 Tooltip 拼接属性字符串**：长内容不可控制宽高和层级。
- **装备槽左键直接卸下**：效率高但不可发现、易误操作，也无法先查看对比。
- **只用粗体提高正文层级**：小字号 CJK 字体变糊，仍没有解决对比度和留白。
- **成功后统一显示“使用成功”**：玩家不知道实际数值、上限和状态变化。
- **只验证节点可见**：无法证明文字可读、面板未越界或 Tooltip 尺寸合理。

## 自动验证

项目加入了以下 UI 专题检查：

- 按钮状态文件、尺寸、alpha 和运行引用。
- 物品实例与当前角色装备状态、左/右键语义和存档往返。
- 品质色在列表、详情、Tooltip 和日志的一致性。
- 头像源图比例、裁切区域合法性和列表/详情共用逻辑。
- 阅读内容非空、打开/关闭、不消耗物品、不改变任务状态。
- Tooltip 文本、宽高、空内容和边缘位置。
- 使用物品的当前值、上限值、状态解除和失败反馈。
- 模态层级、Canvas/Overlay、世界输入隔离和 Esc。
- 引擎 editor/headless 解析、目标 UI 场景和截图工具。

共享项目可以直接采用[UI 界面契约模板](../templates/ui-screen-contract.template.json)和[UI 界面发布检查表](../checklists/ui-screen-release.md)。

## 人工验收

- 以实际显示尺寸检查中文，不放大原图代替运行画面。
- 对比空、正常、最长中文和极端属性数量。
- 悬停屏幕四角装备，确认 Tooltip 不越界、不变成长条。
- 同时观察品质内框、选中外框和已装备角标。
- 检查全身立绘裁为头像后，脸、头发和肩部仍可辨。
- 用鼠标、键盘/手柄和目标触控设备完成打开、选择、确认、取消、关闭。
- 播放使用反馈、状态悬停和战斗飘字，确认出现时机和锚点稳定。
- 调试层和正式层分别截图，避免 GM/开发信息污染交付证据。

## 结果

界面从“存在一张漂亮底图”转向“状态、资产和交互可验证”。背包、角色、任务、武学、商店、阅读和战斗 HUD 使用统一品质语义、反馈入口和层级规则；装备查看与卸下不再冲突，头像在不同面板保持一致，长文和 Tooltip 有明确边界，自动检查与截图能共同阻止回归。

## 可迁移结论

1. 概念图是构图参考，不是动态界面的运行时规格。
2. UI 必须读取真实业务状态，不能按类型、名称或本地快照猜测。
3. 品质、选中、占用和禁用属于不同信息维度，应分层表达。
4. 默认控件适合默认复杂度；结构化内容需要结构化组件。
5. 操作反馈必须来自业务结果，并展示实际差值和失败原因。
6. 自动测试证明结构正确，固定状态截图证明玩家真的看得懂。
7. 固定展示页和数据驱动界面应采用不同资产接入策略。

## 不适用范围

- 纯影视式线性界面可以使用更多整屏预渲染，但交互热区和本地化仍需单独验证。
- 重度多语言项目需要额外覆盖文本膨胀、双向文字、字体回退和语言切换。
- 无鼠标平台不应依赖右键；次要操作需要映射到手柄、长按或明确按钮。
- 3D 世界空间 UI 还需补充距离缩放、遮挡、视线、深度和 VR 可读性。
- 竞技联机游戏需要进一步定义预测、延迟、重连和权威状态反馈；本案例只覆盖本地面板与业务结果分层。
